# Security follow-up — 2026-11-10

## Deployment contract (important behavior changes)

This build is a **single trusted-operator demonstration**. All sessions and workpapers belong to that operator; UUIDs are identifiers, not authorization credentials. It is NOT suitable for mutually untrusted users sharing an operator account or for production payment/PII workloads.

- `next start` fails closed (503) without `SAAF_OPERATOR_PASSWORD` of at least 24 characters. Set `SAAF_OPERATOR_USER` (default `operator`) and a generated unique password in the deployment secret store, never Git. HTTPS is required. All pages/APIs, including session/list/workpaper endpoints, are behind the Next.js proxy's Basic-auth challenge. Do not use `next dev` as a public service; unconfigured local development intentionally permits access. API callers supply Basic authorization; browsers prompt and use same-origin requests.
- Authenticated cross-origin mutations are rejected. Seeding is POST-only, no longer a mutating GET. Do not bypass the proxy, expose internal route handlers as separate services, or cache authenticated pages at the CDN. Direct unit tests of handlers are NOT authentication integration tests.
- Live judgments run outside DB transactions. A transaction rechecks the full saved snapshot before committing. Conflicts return 409, no action authorized; explicitly re-read and retry. Do not silently retry a stale model judgment.
- JSON is stream-limited before parsing: 1 MiB verify/intercept, 128 KiB forge, 4 KiB rehearsal; provider JSON 64 KiB. Ingress should additionally enforce matching request/time limits and per-operator rate/concurrency limits. These controls are bounded-resource defense, not an availability guarantee.
- Atomic shared-DB budgets: 100 sessions, 200 scans, 100 rehearsal runs; 100 events/session and 2 MiB total session trace. Quota exhaustion refuses new writes (429 for scan/rehearsal, safe HALT/503 for intercept). Existing sessions can update within their event/byte limits. No silent eviction at capacity.
- Demo retention is **30 days** since last session update / run or scan creation. Cleanup deletes expired session/run records AND associated events, checkpoints and workpapers. The canonical scan is kept. Cleanup runs on writes and via authenticated `POST /api/maintenance`; schedule that endpoint if idle-time deletion is required. Export evidence before expiry. This TTL is NOT a regulatory audit-retention policy. Backups/provider retention require separate configuration.
- Workpaper list supports `?limit=1..50&offset=0..10000` (default 25); dashboard shows the latest 50. `verified` values are recomputed, never accepted from DB cache. Detail responses discard stale HTML; verify-by-ID regenerates it.
- Scanning is explicitly heuristic, not certification. Apparent ActionGuard/hash symbols NEVER clear risk warnings, including comments, strings, unreachable branches and trivial assertions. False positives on guarded code are intentional; enforcement requires tests and control-flow review. Source indirection/aliasing is not a solved static-analysis problem.
- Both offline verifiers validate recorded Jev decision ranges, probability sums, choices and normalized result fields. This does not authenticate model responses; unkeyed workpaper hashes prove consistency, not provenance.

## Validation and audit limitations

Run `scripts/security-sandbox.sh` on supported Linux after installing pinned JS dependencies and the Python development environment. It fails closed without namespace/chroot capabilities and an OS cgroup resident-memory cap <=4 GiB. It exports non-secret source without Git/env files, runs in isolated user/mount/network/PID namespaces with isolated loopback only, read-only source/toolchain/dependencies, empty allowlisted environment, capability dropping, and a disposable 768 MiB scratch filesystem. Limits: 240s wall time, 180s CPU per process, 256 processes per user, 128 MiB per file, 64 GiB virtual address space (WASM reservations); resident memory is bounded by the outer <=4 GiB cgroup. No credentials or external sockets are mounted. No dependency installation/network fetching occurs in the sandbox. Output is observed as stdout; no target-generated files are promoted as audit evidence. This validates a disposable copy, not deployed infrastructure.

A fresh independent security reviewer is still required. The current toolset cannot create independent reviewer agents; repeated same-agent tests are NOT independent verification. Upstream schema validators check report format, not truth or completeness. No complete six-phase/100% coverage or production penetration-test claim is made. Deployment credentials, TLS/CDN/proxy behavior, scheduled cleanup, backups and provider access/retention remain owner checks. For a genuine multi-tenant service, replace Basic auth with identity-backed per-record ownership and adversarial two-principal integration tests before use.
